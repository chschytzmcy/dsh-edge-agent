## 修复的两个 bench bug

### Bug 1: Makefile env var 透传(§7.87.9)

`make e2e-benchmark` 用 `NO_THINKING=${NO_THINKING:-1}` 语法 → Make 看到的是空 → bash 子 shell 收到 NO_THINKING= → bench 默认 ON thinking mode → model 全跑 reasoning → score=0

**修法**(`Makefile:91`):
```diff
- @LABEL=${LABEL:-bench} NO_THINKING=${NO_THINKING:-1} bash scripts/e2e-model-quality-bench.sh --label $${LABEL}
+ @export NO_THINKING=$${NO_THINKING:-1}; export LABEL=$${LABEL:-bench}; bash scripts/e2e-model-quality-bench.sh --label "$$LABEL"
```

### Bug 2: urllib 系统代理污染(§7.87.10)

r1 跑出 68/68 **HTTP 502 Bad Gateway**,但直连 curl 跟同样的 body 返回正常 JSON。

**根因**:`no_proxy=localhost,127.0.0.0/8,...,*.aliyun.com` 不含 `67.0.0.5` → Python `urllib.request.urlopen()` 走 `http_proxy=http://127.0.0.1:7890/` → proxy 无法路由 LAN → 502

**修法**(`scripts/e2e-model-quality-bench/harness.py:24-27`):
```python
# §7.87.10 Bypass 系统 HTTP_PROXY
_proxy_handler = urllib.request.ProxyHandler({})  # 所有协议都空 proxy = 直连
urllib.request.install_opener(urllib.request.build_opener(_proxy_handler))
```

`build_opener` 单用不够 —— 必须 `install_opener` 才能替换 default opener。

### Bug 3: intrinsic 并发过高(§7.87.9)

r1 第一版 6 个 category ThreadPoolExecutor 并发 → llama.cpp 默认 parallel=1 → 部分请求 502。

**修法**(`harness.py:1050-1051`):加 `--intrinsic-concurrency` CLI flag,默认 2;对 cloud LLM 仍快,对 27B+ llama.cpp 安全。

## 教训(记 memory)

1. **urllib.request 默认走系统代理**:`urllib.request.install_opener(ProxyHandler({}))` 必须 install,不能只 build_opener;bench 测 LAN LLM 必须 bypass 系统 HTTP_PROXY
2. **no_proxy 默认不含 LAN IP**(67.0.0.5 / 192.168.x):写测试 harness 必须显式 bypass,不能依赖 no_proxy 配置
3. **Makefile env var 透传**:用 `$${VAR:-default}` 语法让 shell 看到默认值,不要用 `${VAR:-default}`(Make 解析时空)
4. **intrinsic 并发上限** = server parallel slot 数:llama.cpp 默认 1,本地 LLM harness 默认 2 worker 安全,cloud LLM 可调高
