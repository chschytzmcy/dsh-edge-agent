## 决策记录

### 已做出的决策

1. **A2 传输层安全暂不实施**（2026-08-22）
   - 原因：当前直接调用 DeepSeek API，无中间中继，OHTTP 价值有限
   - HTTPS 已足够保护传输安全
   - 保留 Phase 8 作为远期规划

2. **RK3588 NPU 优化不在本项目范围**（2026-08-22）
   - 原因：NPU 优化属于硬件驱动层，不在应用层项目范围
   - 使用 rkllm3-server 提供的 OpenAI 兼容 API 即可

3. **A1 采用简化版实现**（2026-08-22）
   - 原因：privacy-policy 策略引擎尚未实现
   - 简化版：纯正则实现，无 TCM/策略引擎依赖
   - 后续 Phase 4 完成后可升级为策略驱动

### 待决策

1. **Phase 3 存储方案**：SQLite vs JSONL？
   - SQLite：支持事务、索引、全文搜索
   - JSONL：简单、易读、易调试
   - **建议**：SQLite（加密扩展成熟）

2. **Phase 4 策略文件格式**：JSON vs YAML？
   - JSON：机器友好，易于签名验证
   - YAML：人类可读，易于编辑
   - **建议**：JSON（安全性优先）

3. **Phase 7 TEE 优先级**：TrustZone vs Keystone？
   - 取决于目标硬件平台
   - **建议**：先 TrustZone（RK3588 已有）

## 总结

本项目采用**渐进式实施**策略：

1. **先跑起来**（Phase 1）— 基础对话功能
2. **再加防护**（Phase 2-6）— 逐步增强安全能力
3. **最后上硬件**（Phase 7-8）— TEE + 零信任

每个阶段都可独立交付，前一阶段是后一阶段的基础。当前处于 **Phase 2（基础安全加固）**，已完成 A1 简化版。

**核心理念**：安全不是一蹴而就的，而是持续演进的过程。
